# 不同环境下如何选协议

**默认建议：REALITY 主用、Trojan 备用；UDP 网络正常时，再比较 Hysteria 2 / TUIC。AnyTLS 适合愿意验证新版客户端兼容性的人；Shadowsocks 仅作兼容备用。**

这是本项目的运维建议，不是协议安全排名，也不保证任何网络都能连接。选择的前提是：使用维护中的实现、正确验证服务端身份、保管好访问凭证。

## 先分清三件事

- **保密与身份校验**：别人能否读懂流量、客户端是否连到了真正的服务器。关闭证书校验会破坏这一层；测速无法补救。
- **可用性与流量特征**：运营商、网络策略是否允许这条连接。TLS 或 REALITY 不等于不会被识别、限速或封禁。
- **性能**：延迟、丢包、拥堵、带宽。UDP、QUIC、新协议、低延迟都不是“更安全”的同义词。

## 环境选择表

| 使用环境 | 优先尝试 | 原因与必须检查的条件 |
|---|---|---|
| 家庭宽带，日常浏览/办公 | REALITY；Trojan 备用 | TCP 通常兼容性较好。REALITY 核对公钥、SNI、short ID；Trojan 必须校验证书。两者最终都要实测。 |
| 酒店、机场等陌生 Wi-Fi | 已正确验证身份的 REALITY / Trojan / AnyTLS | 重点是服务器身份、HTTPS 和代理覆盖范围，不是协议数量。先通过合法的网络登录页；不要为了连通而跳过证书验证。 |
| 网络明确限制 UDP，或 Hy2/TUIC 超时 | REALITY / Trojan / AnyTLS | 使用 TCP 传输。换协议是兼容性选择，不意味着 UDP 的加密更弱；不要反复把带宽参数调高。 |
| 蜂窝网络，或有丢包但 UDP 可用 | 对比 Hysteria 2、TUIC 与 TCP 备用 | QUIC 的行为可能更适合该网络，但运营商、NAT、功耗和拥堵都会改变结果。切 Wi-Fi/蜂窝分别测试，保留 TCP 备用。 |
| 大文件、视频、希望改善拥堵表现 | 实测 Hysteria 2 / TUIC | 测持续吞吐与稳定性，不只看 ping。Hy2 默认忽略客户端带宽提示，使用自适应拥塞控制；不要填写远超实际线路能力的带宽。 |
| 多台不同系统设备，希望省事 | Trojan 或已验证兼容的 REALITY | 先看客户端支持范围。本项目提供三种核心的配置/测试能力，但没有替你验证每个 App 的每个版本。 |
| 想尝试新协议，客户端明确支持 | AnyTLS | TLS 身份验证与连接复用/填充是不同层面。新协议不代表经过更多审计，也不保证速度或抗识别优于其他协议。 |
| 旧客户端只能使用 SS | Shadowsocks AEAD 兼容备用 | 本项目的 chacha20-ietf-poly1305 能加密流量，但不提供前向保密；访问密码泄露后的影响比一次连接失败更严重。优先升级客户端。 |
| 银行、工作账号、敏感资料 | 先确认 HTTPS、端点可信和完整路由，再选维护中的验证型协议 | “美国/日本 IP”“新协议”都不使账号更安全。使用 MFA，避免不必要的频繁切换出口；代理不能替代应用层安全。 |

## 六种协议的实际边界

| 协议 | 本项目的身份验证 | 主要取舍 |
|---|---|---|
| VLESS + REALITY + Vision | REALITY 公钥与握手验证 | 无需为 REALITY 自己申请网站证书。VLESS 本身不是完整的加密保护；本项目固定组合 REALITY + Vision，不导出裸 VLESS。目标站和客户端核心兼容性仍要测试。 |
| Trojan | 公共 CA 证书、IP/域名匹配；服务端最低 TLS 1.3 | 常见 TLS 方案。证书过期或名称不匹配时应修复证书，不能改成忽略错误。 |
| Hysteria 2 | 公共 CA 证书、IP/域名匹配 | QUIC / UDP，需要网络放行相应 UDP 端口。不能因为握手失败就断定服务器坏了。 |
| TUIC | 公共 CA 证书；关闭 0-RTT | QUIC / UDP；0-RTT 有重放风险，本项目不为减少握手延迟而开启它。 |
| AnyTLS | 公共 CA 证书；服务端最低 TLS 1.3 | TCP / TLS，需支持该协议的客户端；主要是另一种实现和传输行为，不是额外安全等级。 |
| Shadowsocks | AEAD 共享密钥认证与加密 | 没有证书不等于没有加密；但此模式无前向保密，当前 Xray 会给出弃用提示。本项目的 Auto 组不会自动选它。 |

## 关于证书和自动切换

六协议默认申请 Let's Encrypt 的 **IP 短期证书**，不需要域名。CA 当前提供的此类证书有效期约六天，因此续期是持续运行条件，不是可选优化。本项目每六小时检查，保留 TCP80 用于 HTTP-01；续期成功会重启 Hy2 与 sing-box，连接可能短暂中断。详见 [Let's Encrypt 官方说明](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)。

已有证书可用 `--tls-mode provided`，但必须覆盖配置中的 IP/域名、完整链可信且私钥匹配。该模式只复制证书，不接管原证书管理器；你需要配置更新到本项目目录及重启服务的部署钩子。未续期会导致连接失败。

六协议配置不使用 `insecure=1`。旧三协议模式的 Hy2 为自签名证书 + 精确指纹；只有确认客户端确实验证指纹才可使用，不能只启用“跳过验证”。两个模式不能混用。

导出的 Mihomo 默认手动选择 REALITY。Auto 组只在前五个协议间比较测试 URL 延迟，不测试安全性，也不代表最大下载速度。同一台 VPS 的所有协议仍是同一个出口；服务器或 IP 整体不可达时，需要另一台独立服务器备份。

## 协议不能替你解决的事

1. **终端和服务器失陷**：设备恶意软件、泄露的 root 密码、未更新的服务端，都不能靠换协议修复。日常维护权限与节点使用凭证应分开。
2. **应用层明文**：代理加密通常只覆盖设备到 VPS。VPS 到目标网站的明文 HTTP 仍不受 HTTPS 保护，应使用端到端 HTTPS。
3. **DNS 和路由覆盖**：本地 SOCKS/HTTP 代理不自动覆盖所有 App、DNS、IPv6 或 UDP。需要全设备代理时使用合适的 TUN/VPN 模式，并检查实际路由；本项目默认配置不承诺“零泄漏”。
4. **匿名与账号识别**：网站仍能通过登录账号、Cookie、设备信息识别用户。代理 IP 不等于匿名身份。
5. **不必要的暴露**：不开公开管理面板、不共享 root、不发布二维码；协议无需全部常开。若只需要三种，可新建 `--profile three`，但已有部署不会自动收缩或迁移。
